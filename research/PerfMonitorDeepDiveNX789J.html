01 — Overview

What is the Performance Monitor?

The Performance Monitor is a system overlay floating bar that appears during gameplay to show five real-time metrics. It renders as a translucent dark pill (#222635 fill, #545353 stroke, 20px corner radius) on top of the game surface. Users toggle it from the GameAssist sidebar tile.

💡 Key Clarification

The bar displays current time, FPS, network speed, battery percentage (%), and game play duration (hours). It does not show "remaining battery time" — the 5th panel shows how long the current game session has lasted (e.g. "1.5h"), which may be what was mistaken for a battery-time estimate.

🕐

Current Time

PerformanceMonitorClock (TextClock)
Forced 24-hour format via is24HourModeEnabled() → true. Uses system TextClock — auto-updates every minute.
📊

Frame Rate (FPS)

FpsTick → FpsDetectManager (Binder IPC)
System-level FPS detection via com.zte.performance.fpsTicker service. Cross-process Binder callback delivers onFps(int fps, float, String pkg, String surface).
📶

Network Speed

TrafficStats API (polled every 1s)
Background thread polls getTotalRxBytes() + getTotalTxBytes() each second. Calculates delta and formats as KB/S, MB/S, or GB/S.
🔋

Battery Level (%)

BatteryManager + BATTERY_CHANGED broadcast
Initial read via BatteryManager.getIntProperty(4) (BATTERY_PROPERTY_CAPACITY). Ongoing updates from ACTION_BATTERY_CHANGED broadcast: level * 100 / scale.
⏱️

Game Play Duration

GameDurationManager (elapsed time)
Tracks per-game session time via SystemClock.elapsedRealtime(). Formats as decimal hours (e.g. "1.5h"). Updated every 60 seconds via mTimeChangeRunnable.

03 — Five Metrics

How Each Metric Works

PANEL 0 Current Time

View type: PerformanceMonitorClock extends TextClock

How it works: Android's TextClock auto-updates its text from the system clock. The subclass overrides is24HourModeEnabled() to always return true, forcing 24-hour display (e.g. "14:32") regardless of user locale settings. It also wraps onDetachedFromWindow() in a try-catch to prevent crash-on-remove edge cases.

Update frequency: Automatic via Android framework (every minute).

Layout XML: layout_monitor_current_time.xml — ImageView icon + PerformanceMonitorClock, text color #FFD7D7D7.

PANEL 1 Frame Rate (FPS)

View type: Plain TextView (id: frame_rate)

Data source: FpsTick → system FpsDetectManager via Binder IPC

How it works:

  • FpsTick extends IFpsTickCallback.Stub — a Binder stub for cross-process callbacks
  • On addFloatView(), calls FpsTick.register() which invokes FpsDetectManager.getInstance().registerCallback(this)
  • The system's com.zte.performance.fpsTicker service starts delivering FPS data
  • Callback signature: onFps(int fps, float unknown, String packageName, String surfaceName)
  • The anonymous inner class AnonymousClass2 overrides onFps() — checks the FPS value changed AND the package matches, then posts updateFps() to the main thread
  • Display format: R.string.frame_rate_template with the FPS integer (e.g. " 60FPS")

Unsupported FPS apps: For streaming/remote-play apps, the bar shows "--FPS" because the actual game runs remotely:

PANEL 2 Network Speed

View type: PerformanceStatusView with app:isBatteryLevelType="false"

How it works:

  • A background-thread Handler posts mRefreshRunnable every 1000ms
  • Each tick reads TrafficStats.getTotalRxBytes() + getTotalTxBytes() — total device network traffic (all interfaces)
  • Speed = (currentBytes − lastBytes) / ((currentTimeMs − lastTimeMs) / 1000.0f) in bytes/sec
  • Adaptive formatting method c(float):
    • < 10 KB → "X.XX KB/S"
    • < 100 KB → "XX.X KB/S"
    • < 1000 KB → "XXX KB/S"
    • < 10 MB → "X.XX MB/S"
    • < 100 MB → "XX.X MB/S"
    • < 1000 MB → "XXX MB/S"
    • ≥ 1 GB → "X.XX GB/S"
  • Only posts UI update if currentBytes != lastBytes (avoids unnecessary redraws when idle)
  • Handles Infinity / NaN edge case → falls back to "0.00 KB/S"

PANEL 3 Battery Level

View type: PerformanceStatusView with app:isBatteryLevelType="true"

How it works:

  • On start (h()): reads initial level via BatteryManager.getIntProperty(4) — constant 4 is BATTERY_PROPERTY_CAPACITY (percentage 0–100)
  • Registers a BroadcastReceiver for ACTION_BATTERY_CHANGED
  • On each broadcast: level = intent.getIntExtra("level", 0) * 100 / intent.getIntExtra("scale", 100)
  • Display format: R.string.battery_level_template with integer percentage (e.g. " 87%")
  • Receiver registered with flag 2 (RECEIVER_NOT_EXPORTED)

Note: This is battery percentage, not remaining time. The code has no discharge rate estimation.

PANEL 4 Game Play Duration

View type: Plain TextView (id: performance_monitor_game_duration)

Data source: GameDurationManager → PerformanceMonitorWindowController

How it works:

  • GameDurationManager is a singleton that implements TopActivityMonitor.FullActivityResumedCallback
  • It tracks game start/stop via SystemClock.elapsedRealtime() and accumulates per-package play time in a HashMap
  • Special handling for WeChat mini-games: com.tencent.mm with non-zero hash gets a compound key pkg@hash
  • PerformanceMonitorWindowController polls every 60 seconds via mTimeChangeRunnable: calls GameDurationManager.p(pkg, callback)
  • The manager calculates live time: storedTime + (elapsedRealtime − startTime) and delivers via CallBack.onBundlePrepare(Bundle)
  • UseTimeUtils.msToH(ms) converts to decimal hours: minutes / 60.0 formatted as "0.0" (≥ 0.1h) or "0.00" (< 0.1h)
  • Display: R.string.game_duration_template (e.g. " 1.5h")
  • If the process is no longer running (q(pkg, pid) returns false), sends null bundle — duration display freezes at last known value

05 — Interaction

Touch Handling & Animation

👆 Touch Logic (method C(MotionEvent))

The entire floating bar is a touch target with drag-to-move and tap-to-collapse behavior:

  • ACTION_DOWN: Records start position (rawX/rawY), cancels auto-fade timer
  • ACTION_MOVE: Updates mPointX/mPointY, calls checkLayoutParams() to clamp within screen bounds, then updateViewLayout() to reposition
  • ACTION_UP: If total drag distance < 24px (Euclidean), treated as a tap → triggers collapse/expand. Otherwise treated as a drag → saves position to SharedPreferences
  • Tap detection: √((endX−startX)² + (endY−startY)²) < 24²
  • Guard: if animation is running (mIsAnimationRunning), ignores all touch events

📦 Tap-to-Collapse (method N(float x))

When the user taps the open bar:

  • Calculates which of the 5 panels was hit via A(float x) — divides bar width into 5 equal zones
  • Stores the tapped index as mLastClickIndex
  • Calculates the panel's X offset, adjusts window position so the tapped panel stays in place
  • Sets window width to that single panel's width
  • Calls V(false) to play the collapse animation

When the user taps the collapsed bar:

  • Gets the collapsed panel's X position
  • Adjusts window X so the full bar re-centers around where the collapsed panel was
  • Sets window width back to full
  • Calls V(true) to play the expand animation

🎬 Animation (method V(boolean expand))

Two synchronized AnimatorSets run simultaneously:

  • Main set — translationX animations for each panel:
    Panels to the left of tapped slide left; panels to the right slide right
    Plus a ValueAnimator on the CornerRectangle width (pill shrinks/grows)
    Collapse: AccelerateInterpolator, 100ms
    Expand: OvershootInterpolator(0.5f), 300ms (bouncy feel)
  • Alpha set — fades out/in the non-tapped panels:
    Collapse fade-out: 100ms
    Expand fade-in: 50ms
  • On collapse animation end: calls addOpenOrShortenWindow(true) — removes the full layout from WindowManager, adds the shorten layout with the single chosen panel

👻 Auto-Fade

5 seconds after the last touch (or after initial display), the bar fades to 50% alpha via mFadeRunnable. Any touch cancels the timer and restores full opacity. When the user lifts their finger, the 5-second countdown resets.

🎮 Game Lifecycle Integration

PerformanceMonitorController implements GameMonitor.Callback:

  • onGameStart() → if toggle is on, delays addFloatView by 800ms (normal) or 1100ms (first activity create)
  • onGameStop() → removes float view, cancels pending add
  • onGameUpdate() → updates the current package name on the existing window
  • executive("statusbar_show"/"statusbar_hide") → adjusts position constraints for fullscreen mode changes

Also implements HostMonitor.Callback for dual-screen/mirror display support — creates a separate window on the secondary display.

📊 Analytics Tracking

On every unregister (toggle off or game exit), logs to NubiaTrackManager:

  • app_name — current game package
  • size — "all" (full bar) or "single" (collapsed)
  • item — if collapsed, which metric: "current_time", "framerate", "speed", "electricity", "play_time"
  • duration — seconds the bar was active, formatted as "X.X"
  • Tracked to event "performance_board_used" under package "cn.nubia.gamelauncher"
